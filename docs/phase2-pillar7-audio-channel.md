## 0. なぜ書くか — 隠すのではなく「証明する」

電子透かし(watermark)には 2 系統ある。本メモは後者だけを扱う。

- **隠すだけ(steganography)** — 不可聴/不可視のコードを埋める。だが埋め方を知る者は誰でも読め、偽造もできる。これは「権利主張型」の発想で、プロジェクト第一条「嘘では逃げられない」に届かない。
- **証明する(keyed / signed watermark)** — 埋めるコードが**発行者鍵で署名された payload**。誰でも真正性を検証でき、発行者以外は正しいコードを作れない。

「著作権コード」として意味を持つのは後者。すなわち **鍵付きの潜在チャネル(柱6)を、音・ノイズという物理担体(柱7)に乗せる**。
埋め方(carrier・変調方式)は公開してよく、秘密は鍵だけ(柱10「型と秘密の分離」)。security by obscurity に依らない。

原則は視覚チャネルと同一: **AI/信号処理は「耳」(雑音・再録音・圧縮への頑健性)、cord は「約束」(真正性・改ざん検知・新鮮性)**。

## 1. 何をするチャネルか

cord の本質的な証明(署名・ハッシュ・nonce・潜在 payload)を、**音響波形そのものに埋め込む**。

```
  発行側: cord ──[変調 render]──> 音波形(WAV/スピーカ/楽曲・環境音に溶込み)
  受信側: マイク録音 ──[復調 extract + 誤り訂正]──> cord ──> 検証(柱9/4/8/10)
```

### 想定ユースケース
- 配信音源・ナレーション・通知音に「これは正規発行物である」という不可聴の発行者印を載せる
- 印刷物の QR(視覚)と二重化し、片方が劣化しても他方で真正性を拾う(クロスモーダル冗長)
- 放送・会場アナウンス等、コピーが容易な媒体での出所証明

## 2. 脅威モデル(担体では防げないものを見極める)

| 脅威 | 音響担体自体で防げるか | 防御の置き場所 |
|---|---|---|
| 盗聴(録音される) | ✗ | 担体に秘密を載せない。表は検証可・裏は柱6 で発行者のみ可読 |
| 改ざん(波形加工) | △(AEAD タグで検知) | 柱9 AEAD + 卵の鎖。割れたら型(seq)のみ露出(柱10) |
| **コピー/リプレイ(録音を再生)** | **✗** | **プロトコル側**: per-copy nonce 一回性 + 鮮度窓 + 柱8 煙 |
| 担体すり替え | △ | 発行者署名(柱4 片割れ)。秘密なしに正しい透かしを作れない |
| 再録音(アナログホール)・非可逆圧縮・残響/環境雑音 | — | **頑健性の問題**(誤り訂正・拡散・低容量化で耐える)。保証ではない |

> **最重要(視覚チャネルと同一の教訓):** 音をコピーすれば透かしごとコピーされる。
> 透かしは「発行者 X 由来」は証明できても「この 1 コピーが許諾済み」までは言えない。
> → リプレイ防止は**チャネルでなくプロトコル**へ。per-issuance の nonce(鎖先端 tip)一回性検証 +
> 公開時刻軸の鮮度窓 + 再提示検知時の煙(柱8)。**`src/visual.js` の FreshnessGuard をそのまま流用できる。**

## 3. 担体設計(音響・3 層 + 変調)

### 3.1 容量・頑健性のトリレンマ
電子透かしは **不可聴性 × 頑健性 × 容量** を同時に最大化できない。著作権証明では:
- **頑健 × 低容量**に振る(数百ビットの署名ダイジェストが再エンコード後も残ればよい)。
- フル payload が要るときは時間方向に冗長反復(動画フレーム間 ratchet と同発想)。

### 3.2 3 層構造(目玉のノイズの音響版)
```
  L1 風景層(柱2)   … 人の耳には「ただの音楽/通知音/環境音」。可聴コンテンツ
  L2 潜在層(柱6)   … 発行者だけが読める裏 payload。心理音響マスキング下に潜む
  L3 検証層(柱9/4) … 署名ダイジェスト・tip・nonce。受信側が cord として検証
```
3 つの聴き手(人/信号処理/発行者)が役割分担 = 調和。

### 3.3 変調方式の候補(鉄板技術のみ・新発明しない)
| 方式 | 性質 | 用途 |
|---|---|---|
| スペクトラム拡散(Cox 型) | 頑健・低容量・鍵で拡散符号 | L3 署名(頑健透かし) |
| QIM(量子化指標変調) | 中容量・準頑健 | L2 payload |
| 心理音響マスキング(MPEG 聴覚モデル) | 不可聴化の核 | L1 への溶込み |
| エコー隠蔽 / 位相符号化 | 古典的音声ステグ | 補助 |
| 近超音波(~18–20kHz, data-over-sound) | 可聴域外・近距離 | 別経路の冗長 |

> **不可聴化(心理音響マスキング)は重い**。まずは「可聴だが頑健」な一周を通し、不可聴化は後段アダプタに切る
> (視覚チャネルで「実ピクセル/ECC は後回し」としたのと同じ判断)。

### 3.4 頑健 / 脆弱 / 準脆弱の使い分け
- **頑健透かし**(L3 署名)= 圧縮・再録音に耐え「出所」を証明。
- **脆弱透かし** = わずかな加工で壊れ「改ざん」を示す → 柱8 の煙に接続。
- 両者を併載すると「出所は本物・だが加工された」を同時に語れる(柱3 `−` 差分発火の音響版)。

## 4. プロトコル骨子(擬似)

```
発行 (emit):
  cord = seal(payload, secret, ctx, { axes, nonce })       // 柱9/1/4 既存
  cord = embedSubliminal(cord, secret, 著作権/発行者印)      // 柱6 既存(src/subliminal.js)
  wave = renderAudio(cord)                                  // ★Phase 2 新規: cord -> 音波形(変調)
  play(wave) / writeWav(wave)

受信 (receive):
  rec  = capture(microphone)
  cord'= extractAudio(rec)                                  // ★Phase 2 新規: 復調 + 誤り訂正 -> cord
  if not fresh(cord'.nonce, cord'.kdf.epoch):
        smokeLog.raise('replay-or-stale', …); reject        // 柱8/10(FreshnessGuard 流用)
  text = guardedOpen(cord', secret, smokeLog)               // 柱9/4/8/10 既存
```

★ が Phase 2 新規 = `renderAudio`(cord→波形)と `extractAudio`(波形→cord)の 2 関数。
**既存 9 柱・FreshnessGuard・SmokeLog には触れない**。音響チャネルは既存 cord を包む薄い物理層ラッパとして足す。
`src/visual.js` の鏡像(担体がテキストフレーム → 音波形に替わるだけ)。

## 5. Phase 2 での実装単位(進捗)
1. ✅ `src/audio.js` — `renderAudio(cord) -> Int16Array` / `extractAudio(samples) -> cord`。
   BFSK(16kHz, 2k/4kHz, 16 sample/bit)+ 自己記述フレーム(`preamble|len|payload|sha256[4]`)
   + WAV(PCM16/mono)入出力。実ピクセルを載せなかった視覚版と同じく、実音響=可聴 FSK に留め不可聴化は後回し。
2. ✅ freshness — `src/visual.js` の `FreshnessGuard` を import 共有(nonce=tip 一回性 + 鮮度窓)。
   `reviveBuffers` も visual から共有(export 追加)。`src/freshness.js` への正式切り出しは引き続き候補(§7)。
3. ✅ リプレイ/改ざん検知 → `SmokeLog` 連携(`replay-or-stale` / `tamper`)。`receiveAudio` が束ねる。
4. ✅ 誤り訂正 = `src/ecc.js`(Reed-Solomon, 視覚担体と共有)。`renderAudioEcc` が payload+cksum を
   RS 保護(プリアンブル 0xEC)。`extractAudio` がプレーン/ECC を自動判別し訂正、能力超過は checksum で安全拒否。
   demo:audio の §3 で「プレーン=復元不能 / ECC=訂正」を実演。再録音同期・更なる頑健化は継続。
5. ⏳ 心理音響マスキングで不可聴化(MPEG 聴覚モデル)= 物理層の最果て。依存が要るため別腹。
6. ✅ デモ `examples/audio-demo.js`(発行 → WAV → 復調 → 雑音/リプレイ/鮮度切れ拒否)。`npm run demo:audio`。
7. ⏳ 実マイク同期(前置同期・タイミング復元)。現 POC は試料整列前提の往復。

## 6. 非目標(やらないこと / 誤解の予防線)
- 「隠すだけ」の透かしは作らない(必ず鍵付き=証明可能にする)。
- 信号処理/AI に暗号判定をさせない(頑健性のみ)。
- 音響担体でリプレイ/コピーを防ごうとしない(プロトコルで防ぐ)。
- 不可聴性を最初に追わない。まず「可聴だが頑健」で一周を通す。
- 新しい暗号プリミティブを発明しない(鉄板技術のみ)。
